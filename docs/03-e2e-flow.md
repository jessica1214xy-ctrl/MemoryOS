# 端到端全流程文档 · 扩展设备记忆代理

> 配套：PRD（docs/01）、设计（docs/02）、集成方案（docs/00）。描述从"终端捕获"到"用户续接/提醒"的完整链路。

---

## 1. 总体架构

```
[终端采集层] 微信小程序 / 原生 App / Web
      │  (统一映射为 TimelineEvent, device_source 标记)
      ▼
[同步网关]  鉴权(user_id) → 设备校验 → 离线队列补偿
      ▼
[中心化记忆服务]  时序存储 + 语义合并 + 向量索引(pgvector)
      ▼
[Agent 层]  跨端续接 / 主动提醒规则 / 知识库问答(RAG)
      ▼
[体验层]  四模块 UI（多端一致） + 提醒三通道分发
```

---

## 2. 用户旅程（E2E 场景）

### 场景 A：微信沟通 → 自动记忆 → 主动提醒
1. 用户微信和导师确认"实验 C 用内部语料"；
2. 小程序授权后捕获该聊天片段 → 映射为 `TimelineEvent(device_source=wechat)`；
3. 服务端生成自动记忆卡"上次和导师聊到哪"；
4. 3 天后该收藏/片段未跟进 → 触发提醒"该跟进实验 C 了"；
5. 用户在当前设备（手机）收到一次提醒 → 处理 → 状态跨端同步。

### 场景 B：跨设备续接
1. 用户在电脑看论文到第 11 页（断点）；
2. 手机打开小程序 → 首页顶部出现"上次在电脑看到第 11 页"；
3. 用户点击确认 → 跳转该论文上下文继续。

### 场景 C：原生 App 无感补全
1. 用户复制一段文献摘要（剪贴板）；
2. 原生 App（已授权）后台捕获 → 增量上报；
3. 知识库问答"实验 B 结论"时作为引用来源出现。

---

## 3. 数据流转

- 采集：终端异构数据 → 标准化为 `TimelineEvent`（沿用现有类型定义，新增 `native_app` 源）；
- 同步：增量上报（HTTP/SSE），离线本地队列，恢复后补传；
- 存储：用户隔离（多租户 `user_id` 过滤后再检索），向量统一构建；
- 检索：问答走向量召回 + 引用溯源，演示模式回退关键词检索。

---

## 4. 关键流程时序（跨端续接）

```
手机端        同步网关        记忆服务        Agent层
  │  打开首页    │                │              │
  │────────────>│ 鉴权(user_id)  │              │
  │             │───────────────>│ 取最新断点事件│
  │             │                │─────────────>│ 按 device_source 组织
  │<────────────│<───────────────│<─────────────│ 返回续接上下文
  │ 展示"上次在A做到哪"                        │
  │ 用户点击确认 │                │              │
  │────────────>│ 请求续接详情   │              │
  │<────────────│<───────────────│ 返回上下文    │
  │ 跳转续接     │                │              │
```

---

## 5. 异常与降级

- 上报失败：本地队列重试（指数退避），不阻塞 UI；
- 同步网关不可用：终端展示"离线模式"，恢复后补传；
- 大模型不可用：问答回退演示检索（界面标注）；
- 续接误判：必须用户确认再跳转，避免打断；
- 隐私撤销：关闭后停止上报，历史数据可导出/删除。

---

## 6. 监控与度量

- 采集成功率、端到端延迟（采集→时间线出现 < 30s）；
- 续接点击率、提醒去重命中率、跨端状态同步时延；
- 隐私开关使用率、授权转化率（小程序→原生 App）。
